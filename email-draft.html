Can a spectral gradient-filtering optimizer cut through the noise in financial time-series data?

Autonomous AI Safety Research Report · 1 August 2026 · Original idea · RUN INCOMPLETE

What We Investigated

We tested whether the Spectral Optimizer — an existing gradient-filtering wrapper from a prior project — improves out-of-sample prediction when training neural networks on large, extremely noisy financial data. The optimizer computes the gradient of the loss for each individual training sample, builds the matrix of similarities between those per-sample gradients, and keeps only the gradient directions that many samples agree on (using a threshold from random matrix theory, the Marchenko–Pastur bound). The hypothesis: financial return prediction is a very low signal-to-noise regime, so filtering out "noise" gradient directions should help a model generalize instead of memorizing noise.

The test bed was the Numerai dataset (v5) — a large public tournament dataset of obfuscated stock-market features with era-based (time-blocked) train/test structure, widely regarded as a canonical noisy financial benchmark. The plan compared the Spectral Optimizer against a well-tuned AdamW (the standard Adam optimizer with decoupled weight decay) on a small multi-layer perceptron (MLP), with a recurrent GRU (Gated Recurrent Unit) arm as a stretch goal, under a pre-registered statistical protocol: strict temporal separation between tuning and verdict data, multiple random seeds, and block-bootstrap confidence intervals.

Bottom Line

The run terminated before answering the headline question — an orchestration failure, not a scientific one (details below). The final head-to-head GPU experiment actually finished on the cluster, but its results were never retrieved or analyzed, so no helps/hurts verdict was computed. The run did bank one substantive scientific result along the way: a proof that the optimizer's "consensus" mechanism cannot see the prediction target at all on this class of task (single-output regression) — what it filters reflects the structure of the input features, not the signal being learned. Approach

All experiments used the existing SpectralConsensusFilter implementation (reused from the prior optimizers project, per the original request — not recreated), wrapped around AdamW, training a small MLP (~200k parameters) on 705 features from the Numerai v5 dataset, on a single NVIDIA L40 GPU on the MATS cluster. The protocol was unusually strict for an autonomous run: hyperparameter tuning was confined to a 388-era tuning block, a 4-era embargo separated tuning from a held-out 255-era verdict block, the filter mode and all thresholds were frozen before any verdict data was seen, and the planned comparison had four arms — filter-on, filter-off (identical config), a random-subspace control (project onto random directions of the same dimension, to separate "the spectral choice matters" from "any projection helps"), and a Gradient Agreement Filtering baseline.

The headline metric is mean per-era Numerai correlation — the correlation between the model's predictions and true stock returns, computed within each time period ("era") and averaged. On this benchmark, legitimately good models score roughly +0.01 to +0.04; suspiciously higher usually means data leakage. The pre-registered bar for a "helps" or "hurts" verdict was a paired difference of at least 0.004 with a bootstrap confidence interval excluding zero.

Surprising Findings

  1. The optimizer's core diagnostic is provably blind to the prediction target on this task. For any model with a single output trained with mean-squared error, each sample's gradient is just (prediction error) × (a direction that depends only on the inputs). After the normalization the filter applies, changing the targets can only flip signs — and the experiment proved this leaves the entire eigenvalue spectrum the filter relies on exactly unchanged (verified numerically to 10−15). So on regression tasks like this one, the "consensus" the filter detects is structure in the input features, not agreement about the signal. This also explains, retroactively, why the prior project's MNIST classification results were target-sensitive: multi-class cross-entropy gradients don't factor this way. This is the run's banked deliverable — a clean boundary result for where the method's mechanism can and cannot apply.
  2. The filter is an amplifier, not a shrinker. The filtered update exceeded the plain averaged gradient in size on 25–70% of training steps — the filter discards components that point in conflicting directions and effectively amplifies what remains. The mental model of it as "gentle denoising shrinkage" is wrong.
  3. The winner's curse showed up on schedule. The best tuned baseline configuration scored +0.0196 in the hyperparameter sweep but only ~+0.014 when re-run on fresh seeds — a textbook illustration of why the protocol froze its effect-size threshold using the seed-replicated number, not the sweep winner.
